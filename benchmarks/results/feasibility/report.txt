Method
------
Program source is read from a file. Benchmark data reaches stdin through a regular file,
matching upstream bench redirection. The upstream algorithms, common.scm, and result
predicates are unchanged. A successful numeric CSV marker is required for a pass.

This branch lacks (scheme time). --benchmark-time installs a runner-only clock library:
monotonic microsecond current-jiffy, jiffies-per-second=1000000, and POSIX current-second.
The latter is a wall-time approximation, not TAI. The upstream primary elapsed interval
uses monotonic jiffies. No other missing libraries were patched or aliased.

Smoke: reduced problem sizes and one repetition, 5s process wall budget, 1 GiB address-space cap.
One-iteration: original problem sizes and predicates, repetition count one, 3s budget, 1 GiB cap.
Original-string: exact upstream string.input (100 repetitions, size 500000), 10s budget, 1 GiB cap.
Process timing includes startup, parsing, and compilation; benchmark_seconds is the upstream timed region.
All reported times are single runs. Reduced profiles must not be compared with published full scores.

Concrete blockers
-----------------
- Missing library registrations: (scheme inexact), (scheme cxr), (scheme complex), (scheme char).
- File benchmark failures include unbound file-exists? and call-with-input-file.
- CoreIR: Cannot inline stmt chain with If statement (clone not implemented), e.g. N-Queens/quicksort.
- Bytecode: SIGSEGV on ctak (including the reduced case); tak and fibc also crashed in the larger sweep.
- Bytecode conform produced the upstream INCORRECT marker.
- pi reported Division by zero on all evaluators at its upstream problem size.
- Full string repetition count reached the configured memory ceiling; allocation/GC profiling is needed.

Reader transport and validation notes
-------------------------------------
An initial adapter trial used a pipe. The current non-seekable InputPort reader returns
inexact numbers for integer tokens and has a smaller datum grammar. Those trial results
are excluded. Matching upstream regular-file stdin selects scheme_reader and fixes those
adapter-induced failures without changing the evaluator. Batch integration checks cover
both transports. equal.scm hardcodes its repetition count: its input must remain unchanged.
That exception was revalidated; one-iteration/equal-correction.json records the correction.

Reproduce from the ZombieScheme repository root
----------------------------------------------
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DZOMBIE_BUILD_TESTS=OFF
cmake --build build-release --target zombie-scheme -j8
python3 benchmarks/test_batch_runner.py --exe build-release/zombie-scheme
python3 benchmarks/run_r7rs.py --suite /mnt/c/work/r7rs-benchmarks --profile smoke --evaluators lisp bytecode coreir toyvm --timeout 5 --output /tmp/zombie-smoke-new
python3 benchmarks/run_r7rs.py --suite /mnt/c/work/r7rs-benchmarks --profile one-iteration --evaluators lisp bytecode coreir toyvm --timeout 3 --output /tmp/zombie-compat-new
python3 benchmarks/run_r7rs.py --suite /mnt/c/work/r7rs-benchmarks --profile original --benchmarks string --evaluators lisp bytecode coreir toyvm --timeout 10 --output /tmp/zombie-original-new

The script returns nonzero if any case fails. Use a new output directory for each run.
Per-profile CSV/JSON, metadata, exact inputs, generated programs, and stdout/stderr logs
are preserved alongside this report. matrix.csv summarizes the 57-name sweep.
